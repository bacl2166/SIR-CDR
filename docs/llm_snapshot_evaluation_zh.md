# 物品目录漂移后的评测恢复

## 证据与边界

2026-10-17 Phones → Electronics 诊断显示：原生和受控配置下，重复计算物品目录均不完全相同；固定同一目录后，用户编码一致。受控 FP32 配置将最大检索分差从约 0.00879 降到约 0.00000191，但没有消除漂移。该证据将问题定位到目录重计算路径，尚不足以证明是哪一个 GPU 算子导致。

训练已经完成 15 轮，无需因本次评测故障重新训练。训练权重、数据划分、已选 checkpoint、训练身份和原生失败报告均保留。训练时的验证结果仍按原训练记录披露；本次流程不会重新选择训练 epoch。

## 新的评测执行策略

入口：`experiments/recover_llm_evaluation.py`，由 `run_llm_fast.py --action run` 自动调用。

1. 严格核对原 checkpoint 的代码、库版本、配置和数据资产签名。
2. 只把物品侧投影、图传播和原型模块临时移至 CPU，以单线程 FP32 连续计算两次；完全一致才保存目录快照。图仍只来自训练交互，无验证或测试标签。恢复模块设备，不修改 checkpoint。
3. 用户侧继续在 GPU 上执行 Qwen 两步隐推理及 SID 评分，使用 FP32、math SDPA、确定性算法，关闭 TF32 和 cuDNN。所有阶段复用同一目录快照。
4. 完整验证集缓存保存原始检索分数和生成分数；按原有 17 个有限参数方案搜索。先要求 R@5、N@5、R@10、N@10 均不低于**本次策略下的运行配置锚点**，再依 N@10、R@10、N@5、R@5 选择。该条件不代表保证优于旧的数值策略或论文结果。
5. 独立进程重新加载相同 checkpoint 和目录，对完整验证集再次评分。候选、原始分数、正样本 ID、最终排序及各项 R/N 指标必须完全相同。即使指标相同而分数不同，也拒绝进入测试。
6. 核验通过后固定参数，测试集评测一次，保存原输出目录的 `test.json` 和 `test.lock`。已有测试结果或失败预约不自动删除，不允许继续验证调参或覆盖测试。

同分排序固定为“分数降序、物品 ID 升序”。不舍入分数、不增加随机扰动、不按正样本标签处理同分，不放宽核验阈值。R/HR 与 N/NDCG 仍采用现有单正样本评测定义，已见交互按原规则屏蔽。

目录快照、验证缓存、选参报告、核验报告均绑定训练身份、checkpoint SHA、评测代码、执行策略和 GPU 环境。部分验证缓存可断点续算；服务器关机后操作锁自动释放。测试阶段中断会保留失败预约，需单独审查，不能借故重复挑选测试结果。

## 运行与恢复

更新代码后，在原环境执行：

```bash
python -u experiments/run_llm_fast.py --action run
```

默认依次处理 Phones → Electronics、Sports → Clothing。完成的训练由原身份检查复用，不重训。每组改用独立的 `artifacts/tuning/<数据组>_<实验标签>_seed42_snapshot_eval_v1/`，不覆盖旧的原生缓存和选参审计。只恢复 Phones 评测可执行：

```bash
python -u experiments/recover_llm_evaluation.py --pair phones_to_electronics
```

日志依次出现 `SNAPSHOT CACHE`、`SNAPSHOT VERIFY`、`SNAPSHOT TEST`。核验须同时看到 `raw_scores_equal`、`rankings_equal`、`verified_all_metrics` 为 true，各差值为 0。若仍失败，停止并检查报告，不绕过门禁。

## 实验披露

- 这是数值执行策略修正，不是模型训练改进；不能宣称与原生 GPU/BF16 评测逐位等价。不同方法应使用相同数据与评测定义，披露各自数值精度和运行成本。
- 保留并披露此前的验证搜索：原融合搜索 21 组，参数搜索最多 17 组；新策略另搜索 17 组。不得把累计预算写成只有 17 组。实际执行次数以保留报告为准。
- 不使用测试结果决定精度、目录实现、参数或 checkpoint。此前已看过的其他模型/旧实验测试指标应披露；本流程的测试门禁不能抹除整个研究历史中的测试反馈。
- 本地小型真实 Qwen 测试覆盖训练后恢复、快照复用、精确核验、差异阻断和测试锁。实际服务器 CUDA 仍必须通过完整验证核验，不能用本地 CPU 检查替代。
- 此流程只启用前两组 Amazon 任务。Douban Book–Movie 资产与 GenCDR 数据及协议对齐尚待完成；前两组也仍需核对原论文的用户/物品筛选、划分和候选目录，不能据此直接宣称与论文表格完全公平可比。
