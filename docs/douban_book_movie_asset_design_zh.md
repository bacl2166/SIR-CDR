# Douban Book–Movie 第三组资产设计及 GenCDR 对比判定

**执行更新（2026-10-18）：** 第三组处理器、资产编排和 0.6B 推荐入口现已实现，
本地真实预处理完成。按用户后续要求，划分与前两组 Amazon 规则对齐，包括保留重复交互。
最新状态和命令见 [Douban 运行说明](douban_execution_zh.md)。本文余下内容是原设计记录，
“尚未完成”的阶段状态以最新说明为准；与论文同条件比较的限制仍适用。

日期：2026-10-15。基线只指 hupeiyu21/GenCDR。第三组逻辑名称只使用
`douban_book_movie`。本文规定后续构建与验收，不表示全部步骤已实施。

## 1. 目标和限制

保留 SIR 用户侧 Qwen3-0.6B、LoRA、结构投影、两步持久记忆隐推理、CPF
及现有推荐评分；物品侧继续用 Qwen3-Embedding-8B。先完成前两组实验，
第三组通过独立目录加入，不复用旧第三组的用户映射、SID 或 checkpoint。
这是一项新数据实验；已有模型不能通过改目录名变成 Douban 模型。

“采用同一来源数据”“采用同一评估协议”“复现论文结果”是三个不同层次。
最终对比必须声明属于哪一层，不能仅凭文件名或样本数量判断对齐成功。

## 2. 数据流及每阶段产物

| 阶段 | 输入 → 输出 | 验收要求 |
|---|---|---|
| 原始资产 | 发布者 Version 1 ZIP → 原始文件哈希清单 | ZIP CRC、固定 SHA256、五个必需 TSV，保留原始 ID |
| 源数据审计 | 原始评论 → 人群/目录/日期/重复交互报告 | 明确与 GenCDR 表 1 的差异，禁止按测试表现筛数据 |
| 协议冻结 | 作者最终快照，或双方共同重跑的协议 → protocol.json | 来源、ID、排序、留出位置、过滤、人群、候选集全部固定 |
| 切分转换 | 冻结事件表 → 两方向 train/validation/test、mappings | 逐样本比对正例及历史；所有被排除事件与原因可追溯 |
| 物品文本 | 静态内容或允许的训练信息 → item_texts.jsonl | 不加入验证/测试评论、评分、流行度等派生信号 |
| 离线语义资产 | 文本 → embeddings → tokenizer/latents/SID | 固定模型版本、训练身份、碰撞率与码本使用率；碰撞可解码到真实物品 |
| 模型实验 | 同一切分 → 各模型验证选择、冻结测试 | 完整候选协议、统一指标、多个随机种子与配置记录 |

原始下载和审计已实现于 `experiments/prepare_gencdr_douban.py`。后续
协议冻结、SIR 转换、第三组 embedding/tokenizer 和推荐训练尚未完成。
现有第三组 YAML 是隔离的前向配置模板，不是资产准备完成证明。

## 3. 两条有效的对齐路径

### A：与论文原始结果同条件比较

取得 GenCDR 作者实际使用的最终用户/物品映射、排序后的交互、切分和
评估脚本/设置。核对目录中的具体 ID 与每个留出正例，而非只匹配统计数。
将 SIR 接到该协议上运行。原始公开仓库没有提供完整可直接运行的推荐
训练与评测入口，因此仅下载它不能完成这条路径。

### B：共同协议下重新训练基线

若拿不到 A 的数据，冻结一套可复现的 Douban Book–Movie 协议，再让
GenCDR 和 SIR 使用同样输入与评估样本。此时结果标题应为“共同协议
复现”，论文表格数值只放单独参考表。补全的 GenCDR 推荐实现也须披露，
不冒充作者的完整原实现。

B 的人群不能默认决定：若当前 SIR 只支持源域历史非空，则可以预先定义
共有用户子集，并让全部方法共同使用；这会改变论文任务。若目标是覆盖
论文全体单域/双域用户，则需实现并验证 SIR 的无源历史分支，另立版本。

## 4. 协议必须明确的细节

- 两方向：Books→Movies 对应论文 Movies 行，Movies→Books 对应 Books 行。
  先构建统一原始事件表和身份映射，再产生两个独立任务及结果目录。
- 时间：使用真实日期；同一天仅有日期精度，固定原始行序作为可复现
  顺序，不宣称它是真实小时级先后。未知日期不能悄悄补成 0 进入正式实验。
- 留出：每用户目标域末次测试、倒数第二次验证，不将不可达正例替换成
  更容易预测的物品。目标域训练只用留出之前的前缀。
- 源域历史：预测时仅允许时间上已经发生、且协议允许访问的事件；不能
  直接把用户完整源域序列或另一方向留出交互灌入训练图。
- 测试是否允许验证期历史、跨用户时间是否采用全局切分，必须对两模型
  明确一致。逐用户 leave-last-out 不自动等同于全局时间外推。
- 物品身份：使用域与原始 ID 的联合键。若作者确有跨域实体对齐映射，
  必须验证后才能合并；不能因 Book 123 与 Movie 123 数字相同就合并。
- 目录：统一目标域全目录或同一套采样候选。SIR 内部先检索再重排是
  方法的一部分，不能把其候选召回上限隐藏为“全目录生成”。
- 重复正例：当前审计发现 Movies 验证 30、测试 186 个正例曾在历史出现。
  这不是最终共有子集的数量。重复消费任务需允许其参加排序；若定义新物品
  任务并排除这些样本，两方法必须共用固定排除清单，并披露与原论文差异。
- 文本：当前 Books 静态文件只有 book_id/UID，不能从中假定存在书名简介。
  需要另取可追溯静态文本，或明确采用训练交互内的标签聚合。禁止把所有
  评论 labels 汇总后声称完全没有留出信息。文本不足也不能靠编造描述补足。
- 特征：图边、共现、热度和负采样分布只能来自协议允许的训练交互。
  静态全目录物品参与无监督 tokenizer 是转导式设定，需双方允许并声明。

## 5. 身份、缓存与效率

`protocol.json` 应记录数据/转换器 SHA256、方向、排序、过滤阈值、目录、
历史长度、重复正例规则、允许的特征与留出 ID。切分、语义资产、模型与
评测报告逐层记录上游身份，任一不符必须拒绝复用。不同模型、数据方向
和训练目标使用不同输出目录；不得忽略 label_smoothing 等影响训练的参数。

可在双方认可的共享目录内复用同一份静态物品 embedding；不同协议下的
训练标签聚合文本、SID 训练产物和图不能自动复用。调参先复用同 checkpoint
的验证打分缓存，校验缓存与直接评估一致；确有必要才短程微调，避免无意义
重训。不同架构可保留自身训练设置，但披露调参预算、规模、显存与耗时。

## 6. 指标与最终验收

统一 Recall@5/10 与 NDCG@5/10（R@、N@）的实现、平均单位、无正例处理、
候选过滤和并列分数排序。单正例时 Recall 等于 HR；NDCG 因排名折扣通常
低于 Recall，不能通过改定义或缩放强制两者相近。

验证集选择配置与 checkpoint，冻结后执行最终测试。已反复查看并据此
改参的测试结果只能标为探索性；正式确认需要新的有效保留评估方案。
建议至少三个预先指定种子，报告均值与标准差；显著性检验需要保存同一
测试用户的逐样本结果，不能对几个汇总指标做无效检验。

验收清单：相同原始输入、相同样本/留出、相同候选目录与规则、无未声明
信息泄漏、可复算指标、模型身份完整、验证/测试隔离、多种子与资源报告。

## 7. 截至目前的判定

**目前整体结果不适合直接作为“与 GenCDR 论文同条件”的正式基线结论。**

前两组仍可继续跑通和在验证集调参，但历史 SIR 的用户/物品数量与论文
不同，不能只补第三组就认定整张表公平。第三组目前只有原始数据及审计，
其默认筛选规模也与论文不同，尚无新的正式 Douban 推荐结果。

满足 A 或 B，再按共同协议完成各目标域的实验，才适合正式比较。论文
表格每组两域，共六个目标域；只做三个单向任务时只能对对应的三个目标
域作结论，不能声称复现整张表。
